Présentation de l'outil

Bolt.new est un outil de développement full-stack par IA lancé par StackBlitz en octobre 2024. Dans le navigateur, l'utilisateur décrit son besoin en une phrase en langage naturel et obtient une application web complète et exécutable. Il s'appuie sur la technologie WebContainers développée par StackBlitz, qui fait tourner des environnements de développement comme Node.js directement dans le navigateur : le code généré par l'IA peut être prévisualisé, modifié, exécuté et même déployé instantanément, sans aucune installation locale. Dès sa sortie, il est devenu un produit phénomène, transformant « développer une application complète à partir d'un prompt » en outil du quotidien. La technologie WebContainers, à l'origine utilisée dans l'environnement de développement en ligne de StackBlitz, combinée à l'IA générative, a pour la première fois rendu les « applications exécutables générées par IA » accessibles à tous. Depuis 2025, le produit est commercialisé uniformément sous la marque Bolt, au service des développeurs comme des utilisateurs non techniques.

Fonctionnalités clés

D'abord, la génération d'applications à partir d'un prompt. En saisissant par exemple « crée une application de tâches avec connexion », Bolt génère une structure de projet complète — frontend, backend, base de données — et l'exécute directement dans la fenêtre d'aperçu du navigateur.

Ensuite, l'itération conversationnelle. Après la génération, on continue d'affiner par le dialogue : ajuster le style, ajouter des fonctionnalités, corriger les erreurs. L'IA modifie directement le code et rafraîchit l'aperçu, sans jamais ouvrir d'éditeur de code. Plus l'instruction est précise, plus la modification est ciblée : « arrondis le bouton et ajoute une ombre » est bien plus efficace que « rends-le plus joli ».

Troisièmement, l'accès aux fichiers et au terminal. On peut consulter et modifier les fichiers du projet dans l'interface, et exécuter des commandes comme npm dans le terminal intégré, en conciliant « génération sans prise en main » et « contrôle pour les développeurs ».

Quatrièmement, le déploiement et le partage en un clic. Les projets peuvent être déployés sur Netlify, Cloudflare, etc., ou partagés via un lien, ce qui facilite l'envoi d'un prototype à un client ou à des collègues pour validation.

Cinquièmement, les modèles et les intégrations. Il est possible de démarrer un projet à partir des modèles StackBlitz, avec également une intégration GitHub, l'import de maquettes Figma et d'autres capacités, pour s'insérer dans les workflows existants.

Prise en main

En ouvrant bolt.new, la page d'accueil est un champ de prompt. Après connexion, il suffit de décrire l'application souhaitée pour voir une première version fonctionnelle en quelques dizaines de secondes. Cette expérience « prête à l'emploi » est ce qui séduit le plus.

Le parcours type : saisir le besoin → attendre la génération → tester dans l'aperçu → demander des modifications par le dialogue → déployer ou exporter le code. Pour les non-techniciens, il suffit d'envoyer le lien après la deuxième étape pour démontrer ; les développeurs, eux, récupèrent généralement le projet généré en local pour approfondir.

À noter : la consommation. Bolt facture par token ; les conversations complexes et les gros projets épuisent vite le quota. Le forfait gratuit est limité ; une utilisation intensive nécessite pratiquement un abonnement. Par ailleurs, la qualité des résultats dépend de la clarté du prompt : décrire précisément le besoin (pages, interactions, stack technique) améliore nettement le rendu. Autre astuce pratique : découper le besoin en plusieurs petites conversations plutôt que tout mettre dans un seul gros prompt — laisser d'abord l'IA construire le squelette des pages, puis ajouter fonctionnalités et styles par blocs. Le résultat est généralement plus stable et la consommation de tokens plus facile à maîtriser.

Points forts et limites

Points forts : tout le flux se déroule dans le navigateur — zéro installation, zéro configuration, prise en main très simple ; boucle complète de la génération au déploiement, idéale pour valider rapidement des idées et créer des prototypes ; les modifications par dialogue permettent aux non-techniciens de participer à l'itération produit ; le code généré est exportable, pas d'enfermement propriétaire.

Limites : avec la facturation par token, les coûts sont difficiles à estimer et les projets complexes consomment vite ; le code généré supporte mal les scénarios à très grande échelle ou à forte concurrence — les systèmes de niveau production exigent encore une refonte manuelle ; la qualité du réseau est importante, et les performances des gros projets dans le navigateur dépendent de l'appareil ; l'accès direct depuis la Chine continentale est instable.

  • Les utilisateurs non techniques, sans bagage en programmation, qui doivent créer un site ou une petite application ;
  • Les développeurs indépendants qui veulent gagner en efficacité en full-stack grâce à l'IA ;
  • Les contextes comme l'enseignement et les hackathons, où il faut des résultats rapides.

Questions fréquentes

Quel est le lien entre Bolt et Cursor ? Aucun. Bolt vient de StackBlitz et se concentre sur la génération d'applications complètes dans le navigateur ; Cursor est un éditeur de code IA indépendant.

Le forfait gratuit suffit-il ? Il convient pour essayer et pour des prototypes légers ; les tokens sont limités, donc pour de vrais projets, il faudra quasiment passer à Pro.

Le code généré peut-il être utilisé commercialement ? Oui — il peut être exporté et développé en local. Pour un usage commercial, associez-le à vos propres processus de revue de code et de test.

Faut-il installer Node.js ? Non, l'environnement d'exécution est fourni par WebContainers dans le navigateur.

Les applications générées par Bolt sont-elles prêtes à être mises en ligne ? Elles conviennent pour lancer rapidement des prototypes et des applications de taille moyenne ; les systèmes de niveau production devraient être déployés après revue de code, tests et évaluation de sécurité.
