工具简介

Amazon Q 是亚马逊云科技（AWS）推出的生成式 AI 助手家族，2023 年 11 月在 AWS re:Invent 大会上首次亮相，2024 年 4 月 30 日正式全面可用。它并不是单一产品，而是一组面向不同场景的 AI 能力：面向企业的 Amazon Q Business 连接公司内部数据回答问题，面向开发者的 Amazon Q Developer 提供编程辅助（原 Amazon CodeWhisperer），此外还有 Q in QuickSight 等面向具体云服务的版本。对 AWS 客户来说，Q 的意义在于把生成式 AI 能力直接嵌入既有的云工作流，而不必单独搭建 AI 应用。

核心功能

第一是企业知识问答。Q Business 可以接入 S3、SharePoint、Salesforce、Confluence 等数十种数据源，基于企业内部的文档、数据库和系统回答员工问题，并且遵守原有权限体系，用户只能看到自己有权访问的内容。

第二是开发者编程助手。Q Developer 在 IDE 中提供代码补全与聊天问答，也支持命令行操作、代码审查建议，还能协助把 Java 8 等旧版本代码迁移到新版本，这类"代码转换"能力是它区别于通用助手的特色。

第三是生成式 BI。集成在 QuickSight 里的 Amazon Q 支持用自然语言提问来生成图表、仪表盘和数据摘要，降低业务人员做数据分析的门槛。

第四是面向运维的代理能力。Q Developer 可以扮演运维代理，协助排查 EC2、EKS 等环境中的故障，给出修复步骤，部分操作还可以直接代为执行。

第五是企业级治理。管理员可以统一管理用户权限、控制数据源范围、审计 AI 使用记录，这对中大型企业的合规落地很关键。

上手体验

使用 Amazon Q Business 前，管理员需要在 AWS 控制台创建应用并配置数据源连接器，这一步通常需要几分钟到几十分钟，取决于数据源数量。配置完成后，员工通过网页版聊天界面或 Slack 等集成入口提问即可，回答会标注引用的文档来源，方便核对。

开发者侧的上手路径更简单：在 VS Code 或 JetBrains 安装 Q Developer 插件并登录 AWS 账号，免费层即可开始使用代码补全；命令行用户则可以安装 Q CLI，在终端里以自然语言描述任务。

整体体验的关键点是权限：所有回答都受 IAM 权限约束，查不到内容时系统会明确提示"没有权限查看"，这与面向个人的聊天工具很不一样。首次使用的团队建议先从单个数据源试点，确认回答质量与引用准确度后再逐步扩大范围。

优点与局限

优点：与 AWS 云生态深度绑定，数据源连接器丰富，权限模型与现有 IAM 体系一致，安全合规性在同类企业 AI 助手中属于第一梯队；开发者侧从补全到代码迁移的覆盖面完整。

局限：产品线复杂，Business 与 Developer 两套定价和功能边界容易让新用户困惑；对不采用 AWS 基础设施的企业，吸引力大幅下降；回答质量高度依赖数据源文档的质量，知识库整理不佳时效果会打折扣；中文资料的优化程度也弱于面向消费者的通用助手。

适合人群

  • 已经深度使用 AWS 的企业客户，希望在企业内部落地 AI 问答；
  • 使用 AWS 云服务的开发团队，需要编程助手与代码迁移工具；
  • 有严格权限与合规要求的中大型企业；
  • 正在做数据分析和 BI 的团队，希望用自然语言降低分析门槛。

常见问题

Amazon Q 和 CodeWhisperer 是什么关系？ CodeWhisperer 已在 2024 年 4 月更名为 Amazon Q Developer，是 Q 家族面向开发者的部分。

Q Business 能接入哪些数据源？ 支持 S3、SharePoint、Confluence、Salesforce、ServiceNow 等数十种常见企业系统，具体清单以官网为准。

Q 的回答是否安全？ 回答严格遵守企业权限体系，用户只能访问自己有权限的数据，并支持审计。

个人可以用 Amazon Q 吗？ Q Developer 有免费层可直接体验；Q Business 面向企业，需要管理员开通。
