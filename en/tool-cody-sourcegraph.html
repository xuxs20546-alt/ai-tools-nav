📖 Tool Overview

Cody is an AI coding assistant developed by Sourcegraph, and its biggest differentiator is access to Sourcegraph's powerful code search engine. Unlike Cursor or Copilot, which rely on editor-local indexing, Cody can directly access the full-text index of entire codebases hosted by Sourcegraph, giving it an unmatched "field of view" advantage when handling large-scale code problems across repositories and modules — it can not only "see" the files you currently have open, but also the code of every relevant repository across your entire organization.

Cody supports mainstream editors such as VS Code, JetBrains and Neovim, offering code completion, conversational Q&A, code explanation and automatic unit test generation. Its core killer feature is "code-search-driven context" — when you ask where a piece of code is called, Cody instantly returns every call site from the index and injects them into the AI model's context. According to official data, developers at companies using Cody navigate code 45% more efficiently and spend 30% less time on code review. The free tier is open to individual developers; Pro costs $9/month.

🔧 Core Features

Cody's features revolve around "codebase-level context understanding"; its core strength is the global code visibility delivered by the Sourcegraph search engine:

Codebase-level intelligent completion: unlike ordinary completion tools that only look at the currently open file, Cody's completion engine pulls code fragments relevant to your current editing position from the entire codebase via the Sourcegraph index as context. For example, when you are writing a function that calls an internal API, Cody not only completes the function name but also suggests the API's request parameter structure, return types and common call patterns — information drawn from how that API is actually used elsewhere in the codebase.

Cross-repository code Q&A: Cody's most powerful capability is cross-repository understanding. You can ask in natural language "In which microservices is the OrderService.createOrder function called? How do the arguments differ at each call site?", and Cody retrieves all related repositories through Sourcegraph's code search engine, aggregates the call sites and analyzes parameter differences. This capability is extremely valuable in microservice teams — developers no longer need to manually jump between repositories.

Intelligent code refactoring: Cody supports cross-file, cross-repository refactoring operations. For example, if you want to rename a shared library function called by 20 microservices, Cody first searches all references in Sourcegraph, assesses the impact scope, and then applies changes file by file with your confirmation. The generated changes automatically create a branch and open a PR.

Slash commands for quick actions: Cody provides a set of predefined slash commands: /explain (explain selected code), /test (generate unit tests), /smell (detect code smells), /doc (generate documentation comments). Combined with codebase context, these commands produce far higher-quality output than AI tools limited to the current file.

Custom Commands: teams can define their own Cody commands in JSON — for example, create a /review command that instructs Cody to check PRs item by item against the team's code review checklist and output a review report. These custom commands can be shared across the entire team.

🚀 Getting Started

Using Cody happens on two levels: individual developers use the editor plugin, while team admins configure indexing policies on the Sourcegraph platform.

For individual developers, installation is similar to mainstream AI coding plugins: install the Cody plugin from the VS Code or JetBrains marketplace and sign in with a Sourcegraph account (or link your GitHub/Google account). On first use, Cody asks for the Sourcegraph instance URL of your code repository — for public repositories you can directly use Sourcegraph.com's cloud service; private repositories require an admin to first connect the repository and configure indexing on the Sourcegraph platform.

In daily coding, Cody's completion experience is similar to Copilot: gray suggestions pop up automatically as you type. The difference is that when you write code deep inside a large codebase, Cody's suggestions are often more accurate — because it can "see" how the same API is used in other modules. The chat panel supports multi-turn conversations, and each question can manually reference specific files via @-file syntax as additional context.

Team admins configure indexing policies in the Sourcegraph console: select the repositories to index, set the index update frequency, and manage access permissions. Index quality directly affects Cody's search and completion quality — the higher the index coverage, the stronger Cody's cross-repository capabilities.

👍 Pros and Limitations

Pros

❓ FAQ

Q: Does Cody require the Sourcegraph platform?
A: For public repositories, you can directly use Sourcegraph.com's cloud service without additional deployment. For private repositories, an admin must first connect the repository and configure indexing on the Sourcegraph platform (SaaS or self-hosted) before Cody can leverage its cross-repository search advantage.

Q: Can Cody and GitHub Copilot be used at the same time?
A: Technically yes, but the inline completions of the two plugins will conflict (both pop up suggestions at the same time). We recommend choosing one as your primary completion tool and using the other only for conversational Q&A.

Q: Does Cody read my private code?
A: Cody's code indexing and analysis are performed on the Sourcegraph instance you specify. With the enterprise self-hosted version, code data never leaves the enterprise network. For the SaaS version, data handling is subject to Sourcegraph's official privacy policy.

Q: Which programming languages does Cody support?
A: Cody's code completion and Q&A support all programming languages supported by Sourcegraph (including JavaScript, TypeScript, Python, Go, Java, Rust, C/C++ and dozens more). The test framework adaptation for slash commands such as /test varies by language.
