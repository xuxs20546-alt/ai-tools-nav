Über das Tool

Bolt.new ist ein KI-Vollstack-Entwicklungstool, das StackBlitz im Oktober 2024 vorgestellt hat: Nutzer beschreiben ihre Anforderung im Browser in einem natürlichen Satz und erhalten eine lauffähige, komplette Web-App. Es basiert auf StackBlitz' eigener WebContainers-Technologie, die Entwicklungsumgebungen wie Node.js direkt im Browser ausführt — der KI-generierte Code kann sofort in der Vorschau angezeigt, bearbeitet, ausgeführt und sogar bereitgestellt werden, ganz ohne lokale Installation. Nach dem Start wurde es schnell zum Phänomen und machte aus „komplette Apps per Prompt entwickeln" ein alltägliches Werkzeug. Die zugrunde liegende WebContainers-Technologie stammt ursprünglich aus der Online-Entwicklungsumgebung von StackBlitz; in Kombination mit generativer KI machte sie „KI-generierte lauffähige Apps" erstmals für alle nutzbar. Ab 2025 tritt das Produkt einheitlich unter der Marke Bolt auf und bedient sowohl Entwickler als auch nicht-technische Nutzer.

Kernfunktionen

Erstens: App-Generierung per Prompt. Bei Eingaben wie „Erstelle eine To-do-App mit Login-Funktion" erzeugt Bolt eine komplette Projektstruktur inklusive Frontend, Backend und Datenbank und führt sie direkt im Vorschaufenster des Browsers aus.

Zweitens: Dialogbasierte Iteration. Nach der Generierung lässt sich das Ergebnis per Chat weiter anpassen: Stile ändern, Funktionen ergänzen, Fehler beheben — die KI bearbeitet den Code direkt und aktualisiert die Vorschau, ohne dass ein Code-Editor geöffnet werden muss. Je konkreter die Anweisung, desto präziser die Änderung: „Mach den Button abgerundet mit Schatten" funktioniert deutlich besser als „mach es schöner".

Drittens: Datei- und Terminalzugriff. Projektdateien lassen sich direkt in der Oberfläche einsehen und ändern; im integrierten Terminal können Befehle wie npm ausgeführt werden. So verbindet Bolt „Generierung ohne Einstiegshürde" mit „Kontrolle für Entwickler".

Viertens: Ein-Klick-Bereitstellung und Teilen. Projekte lassen sich auf Plattformen wie Netlify oder Cloudflare bereitstellen oder über einen teilbaren Link verschicken — ideal, um Prototypen direkt an Kunden oder Kollegen zur Abnahme zu geben.

Fünftens: Vorlagen und Integrationen. Projekte können aus StackBlitz-Vorlagen gestartet werden; GitHub-Integration, Import von Figma-Designs und weitere Möglichkeiten ermöglichen den Anschluss an bestehende Workflows.

Erste Schritte

Öffnet man bolt.new, besteht die Startseite aus einem Prompt-Eingabefeld. Nach dem Login beschreibt man einfach die gewünschte App und sieht binnen Sekunden die erste lauffähige Version — dieses „Out-of-the-Box"-Erlebnis ist das Überzeugendste an dem Tool.

Der typische Ablauf: Anforderungen eingeben → Generierung abwarten → in der Vorschau testen → Änderungen per Chat anfordern → Code bereitstellen oder exportieren. Nicht-technische Nutzer können nach dem zweiten Schritt einfach den Link zum Demonstrieren verschicken; Entwickler ziehen das Projekt meist lokal und entwickeln dort weiter.

Zu beachten ist der Verbrauch: Bolt rechnet nach Tokens ab. Komplexe Dialoge und große Projekte verbrauchen viele Credits; das kostenlose Kontingent ist begrenzt, intensive Nutzung erfordert praktisch ein Abo. Außerdem hängt die Qualität der Ergebnisse von der Klarheit der Prompts ab — wer Anforderungen konkret beschreibt (Seiten, Interaktionen, Tech-Stack), steigert die Ausgabequalität deutlich. Ein weiterer praktischer Tipp: Anforderungen in mehrere kleine Dialoge aufteilen, statt alles in einen großen Prompt zu packen — zuerst das Seitengerüst bauen lassen, dann Funktionen und Stile abschnittsweise ergänzen. Das liefert stabilere Ergebnisse und macht den Token-Verbrauch leichter kontrollierbar.

Vorteile und Grenzen

Vorteile: kompletter Ablauf im Browser — keine Installation, keine Konfiguration, extrem niedrige Einstiegshürde; geschlossener Kreislauf von der Generierung bis zur Bereitstellung, ideal zum schnellen Validieren von Ideen und für Prototypen; dialogbasierte Änderungen ermöglichen auch nicht-technischen Nutzern die Teilnahme an der Produktiteration; generierter Code ist exportierbar — kein Vendor-Lock-in.

Grenzen: Bei Token-Abrechnung sind die Kosten schwer abzuschätzen, komplexe Projekte verbrauchen schnell Kontingente; der generierte Code unterstützt sehr große oder stark parallele Szenarien nur eingeschränkt — produktionsreife Systeme benötigen weiterhin manuelle Überarbeitung; hohe Anforderungen an die Netzwerkumgebung, und die Performance großer Projekte im Browser hängt vom Gerät ab; direkter Zugriff aus Festlandchina ist instabil.

Für wen geeignet

  • Designer und Produktmanager, die Produktideen schnell validieren und Prototypen bauen möchten;
  • Nicht-technische Nutzer ohne Programmierhintergrund, die Websites oder kleine Apps erstellen möchten;
  • Freelance-Entwickler, die ihre Vollstack-Entwicklung mit KI beschleunigen möchten;
  • Szenarien wie Lehre und Hackathons, in denen schnell Ergebnisse entstehen müssen.

Häufige Fragen

In welcher Beziehung stehen Bolt und Cursor? In keiner. Bolt stammt von StackBlitz und erzeugt komplette Apps im Browser; Cursor ist ein eigenständiger KI-Code-Editor.

Reicht die kostenlose Version? Sie eignet sich zum Ausprobieren und für leichte Prototypen; die Tokens sind begrenzt — für ernsthafte Projekte ist praktisch ein Upgrade auf Pro nötig.

Kann der generierte Code kommerziell genutzt werden? Ja — er lässt sich exportieren und lokal weiterentwickeln. Für den kommerziellen Einsatz empfehlen wir, ihn mit dem eigenen Code-Review- und Testprozess zu kombinieren.

Muss Node.js installiert werden? Nein, die Laufzeitumgebung stellt WebContainers direkt im Browser bereit.

Eignen sich Bolt-generierte Apps für den direkten Produktivbetrieb? Sie eignen sich für den schnellen Launch von Prototypen und mittelgroßen Apps; produktionsreife Systeme sollten jedoch nach Code-Review, Tests und Sicherheitsbewertung bereitgestellt werden.
