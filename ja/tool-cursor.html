📖 ツール概要

Cursor は Anysphere 社が開発した AI ネイティブなコードエディタで、VS Code のオープンソースカーネルをベースに再構築されています。最大の特徴は、AI 機能がエディタのあらゆる操作に深く組み込まれていること——コーディングとチャットでウィンドウを切り替える必要はなく、すべての AI 操作がエディタ内で完結します。Cursor には Tab 補完（Copilot のようなインライン提案）と Composer（複数ファイルにまたがる対話型コード生成）という2つのコア操作モードがあります。Composer モードは Cursor の切り札——複数ファイルにまたがる機能要件を自然言語で説明するだけで、Cursor がプロジェクト構造を自動分析し、正しい場所にコードを作成・変更し、依存関係をインストールするためのターミナルコマンドまで実行してくれます。GPT-4o や Claude 3.5 Sonnet など複数のバックエンドモデルに対応し、必要に応じて切り替えてコストと効果を自由に調整できます。VS Code からの移行ユーザーは、プラグイン・設定・ショートカットをワンクリックでインポートでき、移行コストはほぼゼロです。

✨ 長所・短所

👍 長所

  • Composer の複数ファイル編集は本物のキラー機能： 通常の補完ツールが現在の行にしか影響しないのに対し、Composer はプロジェクト全体のファイル構造を理解し、必要に応じて複数ファイルを同時に変更します——新しいコンポーネントを作成すると、それを参照するすべてのファイルを自動更新します。
  • VS Code からゼロコストで移行： プラグイン・テーマ・ショートカット・settings.json をワンクリックでインポート。従来の開発環境がほぼそのまま移行され、慣れ直す必要はありません。
  • マルチモデルを自由に切り替え： GPT-4o や Claude 3.5 Sonnet など複数のモデルを内蔵。フロントエンドでは安価な GPT-4o-mini、複雑なリファクタリングでは Claude に切り替え——コストを柔軟にコントロールできます。

👎 短所

  • 無料枠はヘビーユーザーには不十分： Hobby 無料版は毎月2,000回の補完＋50回のプレミアムリクエスト。終日コーディングする開発者なら1週間で使い切るかもしれません。Pro 版の月額 $20 も小さくない出費です。
  • クローズドソース製品にはベンダーロックインのリスク： VS Code カーネルベースとはいえ Cursor 自体はクローズドソースの商用ソフトウェア。将来の値上げや方針変更があれば、VS Code への回帰は可能でも、Cursor 独自の AI ワークフローは失われます。
  • 一部の VS Code プラグインに互換性の問題： VS Code 固有の API に深く依存するプラグインは Cursor で正常に動作しない可能性があります。主要プラグインのほとんどは動きますが、必須プラグインは先に Cursor でテストすることをおすすめします。

🎯 おすすめの用途

  • 個人開発者や小規模チームの高速イテレーション： 一人でフルスタックを担当する場合、Composer に機能要件を説明するだけで複数ファイルにまたがるコードを直接生成でき、MVP 開発サイクルを大幅に短縮。アイデアから動作するプロトタイプまで数時間で到達できます。
  • 大規模なリファクタリング： JavaScript から TypeScript へのモジュール移行や状態管理の変更時、Composer に移行ルールを説明すれば、数十ファイルの変更をバッチ処理。手作業よりはるかに効率的です。
  • オープンソースへの貢献とコードレビュー： OSS プロジェクトの PR レビュー時、Chat パネルでモデルを切り替えて変更を分析し、馴染みのないコードの意図を素早く理解。レビューのハードルを下げられます。

💡 活用のコツ

  • Composer のプロンプトが出力品質を決める： 「ログインページを作って」の一言だけでは不十分——使用フレームワーク（React/Vue）、状態管理、UI ライブラリ（shadcn/ui など）、必要なフォーム項目とバリデーションルールを具体的に説明しましょう。具体的なほど生成結果が使えます。
  • @ 記号でコンテキストを指定： Chat で @file・@folder・@web と入力し、AI が参照すべきコードファイルや外部ドキュメントを手動指定。AI にコンテキストを推測させるよりはるかに確実です。
  • 大きな変更の前に Git commit： Composer の一括変更は強力ですが、たまに「やりすぎて」無関係なファイルまで変更します。大きな変更前には必ずコミットする習慣を——失敗しても `git reset --hard` でワンクリック復元できます。

コア機能

Cursor は AI をエディタのあらゆる層に深く組み込んでいます。主なコア機能は以下のとおりです：

1. Composer マルチファイルエージェント——Cursor 最強の機能です。Composer モードでは、複数ファイルにまたがる要件を自然言語で説明するだけで（例：「プロジェクトにユーザー認証システムを追加して。ログインページ、登録ページ、トークン管理、ルート保護を含めて」）、Cursor がプロジェクト構造を自動分析し、正しい場所に複数ファイルを作成・変更し、依存関係のインストールやテスト起動のターミナルコマンドまで実行します。Composer は現在の AI IDE の中でも最高水準のマルチファイル編集体験のひとつです。

2. Tab 補完——Copilot に似たインラインコード提案。Cursor の補完モデルは専用訓練されており、カーソル前後のコードコンテキストを把握できるため、精度と関連性は市販のほとんどの補完プラグインを上回ります。

3. Chat パネル——サイドバーの会話ウィンドウ。@ 記号でファイル（@file）、フォルダ（@folder）、Web ドキュメント（@web）、さらには Git コミット履歴までコンテキストとして参照できます。この精密なコンテキスト制御により、Chat の出力品質はコンテキストを推測するしかないツールを大きく上回ります。

4. マルチモデル切り替え——GPT-4o、Claude 3.5 Sonnet、GPT-4o-mini など複数のモデルを内蔵し、設定からいつでも切り替え可能。モデルごとに強みとコストが異なります：GPT-4o-mini は安価で高速、日常の補完向け。Claude 3.5 Sonnet は推論力が高く複雑なリファクタリング向けです。

5. VS Code エコシステムと完全互換——VS Code の全プラグイン・テーマ・ショートカット・settings.json をワンクリックでインポート。従来の開発環境がほぼそのまま Cursor に移行し、操作習慣を覚え直す必要はありません。

導入体験

Cursor のインストールと導入は非常にスムーズです。cursor.com にアクセスして対応するデスクトップクライアント（macOS/Windows/Linux）をダウンロードし、インストール後の初回起動時にインポートウィザードが VS Code から設定をインポートするか尋ねます。「はい」を選ぶと、すべてのプラグインと設定が数秒で自動移行されます。VS Code を使ったことがない場合は「まっさらな状態から開始」を選べます——Cursor の内蔵機能だけでも十分強力です。

Cursor を初めて使ったときの最も直感的な印象は「Tab 補完が Copilot より賢い」こと——現在の行だけでなく、直前に閲覧したファイルや最近編集した関数も把握し、現在のコーディング意図に合った提案をしてくれます。理解できないコードや変更したいコードに遭遇したら、選択して Cmd+K（Mac）または Ctrl+K（Windows）を押し、「refactor this to use async/await」や「add error handling」と入力するだけ——Cursor が編集済みコードをエディタ内に直接生成し、変更箇所を Diff 形式でハイライト表示します。

Composer の使い方は「AI とのペアプログラミング」に近い体験です。Cmd+I（Mac）または Ctrl+I（Windows）で Composer パネルを開き、実装したい機能を説明すると、Cursor はまずプロジェクト構造を分析（関連ありと判断したファイルを列挙）し、作成・変更予定のファイルリストを提示します。確認して「受け入れる」をクリックすると、すべての変更が一括適用されます。変更完了後も同じ Composer セッションで「ログインページのボタンを青に変更して」や「登録 API にメール形式バリデーションを追加して」と続けられ、Cursor は既存のコンテキストを踏まえて修正を続けます。

よくある質問

Q：Cursor と VS Code + Copilot の違いは？
A：本質的な違いは AI の統合深度です。Copilot は主にインライン補完とチャットサイドバーを提供しますが、Cursor は AI をエディタのコア操作に組み込んでいます（Composer の複数ファイル編集、Cmd+K のインライン編集、@ 記号によるコンテキスト参照）。この深い統合により、AI は「現在のファイルを見る」だけでなくプロジェクト構造を本当に理解できるのです。

Q：Hobby 無料版で足りる？
A：週末コーディングやライトユーザーには十分です。しかし毎日6時間以上コードを書くフルタイム開発者なら、月50回のプレミアムリクエスト枠は3〜5日で尽きる可能性があります。Cursor をメインの開発ツールにするなら、最低でも Pro への加入をおすすめします。

Q：Cursor はコードをクラウドにアップロードする？
A：Cursor はクラウド API 経由で AI モデル（GPT-4o、Claude など）を呼び出すため、リクエスト中にコードのコンテキストが各モデルプロバイダに送信されます。Cursor はユーザーコードをモデル学習に使用しないと公式に表明していますが、コードのプライバシーに極めて高い要求がある場合は、ローカルモデル対応ツール（Cline + Ollama など）を選ぶことをおすすめします。

Q：Cursor はサポートしないが VS Code はサポートする機能は？
A：ほとんどの VS Code 機能は Cursor で正常に動作します。既知の非対応項目には、一部の VS Code 専用拡張機能（Live Share の一部機能など）や Remote Development の高度な設定があります。正式に切り替える前に、必須プラグインを Cursor でテストすることをおすすめします。
