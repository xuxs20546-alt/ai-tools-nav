📖 工具简介

Cursor 是 Anysphere 公司打造的 AI 原生代码编辑器，基于 VS Code 开源内核重构而来。它最大的特色在于将 AI 能力深度嵌入编辑器的每一个交互环节——你不需要在编码和聊天之间切换窗口，所有 AI 操作都在编辑器内部完成。Cursor 提供两种核心交互模式：Tab 补全（类似 Copilot 的行内建议）和 Composer（多文件级别的对话式代码生成）。Composer 模式是 Cursor 的杀手锏——你可以用自然语言描述一个跨越多文件的功能需求，Cursor 会自动分析项目结构，在正确的位置创建或修改代码，甚至帮你运行终端命令来安装依赖。Cursor 支持 GPT-4o、Claude 3.5 Sonnet 等多种后端模型，你可以按需切换，在成本和效果之间自由权衡。对于从 VS Code 迁移的用户，Cursor 一键导入所有插件、设置和快捷键配置，迁移成本几乎为零。

✨ 优劣势分析

👍 优点

  • Composer 多文件编辑是真正的杀手功能：不同于普通补全工具只能影响当前行，Composer 能理解整个项目的文件结构，按需同时修改多个文件——创建一个新组件时，它能自动更新所有引用该组件的文件。
  • 从 VS Code 零成本迁移：一键导入全部插件、主题、快捷键、settings.json，你原来的开发环境几乎原封不动地平移过来，无需重新适应。
  • 多模型自由切换：内置 GPT-4o、Claude 3.5 Sonnet 等多个模型选项，写前端可以用便宜的 GPT-4o-mini，复杂重构切换到 Claude——灵活控制成本。

👎 不足

  • 免费额度对高频用户不够用：Hobby 免费版每月 2000 次补全 + 50 次高级请求，对于全天编码的开发者来说，可能一周就用完了，Pro 版 $20/月是不小的开销。
  • 闭源产品存在供应商锁定风险：虽然基于 VS Code 内核，但 Cursor 本身是闭源商业软件，如果未来涨价或变更策略，迁移回 VS Code 虽然可行但会丢失 Cursor 特有的 AI 工作流。
  • 某些 VS Code 插件存在兼容问题：部分深度依赖 VS Code 特定 API 的插件在 Cursor 中可能表现异常，虽然大部分主流插件正常，但建议先在 Cursor 中测试你的必备插件。

🎯 适用场景

  • 独立开发者或小团队的快速迭代：一个人负责前后端全栈时，用 Composer 描述功能需求直接生成跨文件代码，能大幅压缩 MVP 开发周期，从想法到可运行的 Prototype 只需几小时。
  • 大型重构任务：需要将一个模块从 JavaScript 迁移到 TypeScript，或更换状态管理方案时，用 Composer 描述迁移规则，Cursor 可以批量处理几十个文件的改动，远比手改高效。
  • 开源贡献与代码审查：在审查开源项目 PR 时，用 Chat 面板切换模型分析代码变更，快速理解陌生项目的代码意图，降低 Review 门槛。

💡 使用建议

  • Composer 提示词决定输出质量：不要只写一句"帮我做一个登录页面"——描述清楚使用的框架（React/Vue）、状态管理方式、UI 库（如 shadcn/ui）、需要的表单字段和验证规则，越具体生成结果越可用。
  • 善用 @ 符号引用上下文：在 Chat 中输入 @file、@folder 或 @web 来手动指定 AI 应该参考的代码文件和外部文档，这比让 AI 自动猜测上下文靠谱得多。
  • 重要改动前先 Git commit：Composer 的批量修改能力强大但偶尔会"用力过猛"，多改几个不相关的文件。养成每次大改动前提交的习惯，万一翻车能一键 `git reset --hard` 恢复。
